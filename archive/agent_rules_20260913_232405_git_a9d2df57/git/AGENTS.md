# 协作与评审规则

开始工作前读取 `CLAUDE.md`。本文件只管协作、评审范围与豁免；通用技术规范、项目技术约束、人工决策和迁移规则都在 `CLAUDE.md`。

## 协作

- 在用户明确授权的范围内完成任务，不以正确性、项目风格或额外优化为由突破“只读、不要测试、先停在这里”等限制。发现未解决的规则冲突先指出，不自行扩大权限。
- 实现前先读现有代码，采用满足需求的最简单方案。任务内的常规实现自行完成，不逐步征询；只有真实业务歧义或需要额外授权时才停下询问。
- 需要业务决策时说明场景、实际可行方案、推荐项和代价；不凑方案。工具支持时用选择器，否则文字询问。
- 最终一次交付完整结果，区分静态检查、实际运行验证与未验证项；不在完成后默认开展额外工作。
- 不覆盖其他窗口或 Agent 的改动；只处理当前任务，禁止顺手重构无关内容。

## 评审范围与输出

- review 默认只读，未经明确要求不改代码。范围限用户点名或当前对话已确认的文件及其直接相关改动链路；不因同批 diff、同目录或并行改动而扩展。
- 用户收窄范围后按最新边界执行。无关改动既不审查，也不在结果中提示。
- 默认一次性报告有明确触发条件和因果链的 bug、逻辑错误、安全问题及明确规范违规，附当前文件位置；不以历史结论代替当前代码核实。
- 默认只输出稳定、持续、可复现的缺陷；但会造成持久数据损坏、越权或系统性错账的问题，即使触发窗口短暂也必须报告。已接受自愈窗口和无法证明普通开发流程会稳定触发的本地监听或时间戳理论竞态不报告。
- 字符集、日志、异步分层、Redis Registry、热路径和迁移检查按 `CLAUDE.md` 执行，不在此复制。架构建议仅在用户要求时输出；明确违反既有分层约束的仍应标记。

## 通用豁免

- 本地开发或调试环境允许 Debug 日志打印完整凭据，不作为安全问题报告。生产环境仍须按 `CLAUDE.md` 使用 `tokenMask.js` 脱敏并 AES 加密存储敏感数据；后台创建 API Key 时有意回显一次完整 key 不算泄露。
- Git 索引、未跟踪或未提交等版本控制状态，以及仓库文件权限或模式位，不作为 review 问题。
- AGENTS.md、CLAUDE.md、README 等指导文档的写入和实体说明性注释本身不作为 review 问题；用户点名审查文档内容时仍正常审查。
- schema 评审默认按项目既定流程先迁移再接流量，不重复提示部署顺序；实际违反迁移约束的仍应报告。
